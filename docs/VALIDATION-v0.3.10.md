# Flomo Safe Sync v0.3.10 验证记录

验证日期：2026-09-08。基线：已实时核对的 GitHub main / v0.3.9，提交 `7c634ada4320721dc2b41801064222f86a5d6562`。

## 实现与依据

- 复用既有目录匹配规则与同步记录，只按新目录移动，保留原文件名。
- 保存目录时先持久化迁移意图，再逐文件移动和保存结果；图片移动前后校验 SHA-256。
- Obsidian 属性编辑器可能删除 YAML 注释。目录移动要求唯一、可解析且匹配的 `flomo_slug`；普通正文更新、删除、归档继续使用原有完整受管区校验。
- 开发调研查阅了 [Obsidian 官方 API](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)。实机确认 `FileManager.renameFile` 在未启用总是更新链接时可能弹出询问窗口，因此目录迁移采用公开的 `Vault.rename` 与 `Vault.process`，按迁移前实际解析的链接更新指向。全局链接偏好不变。
- 不移动文件夹整体，不处理未记录的个人附件。其他笔记仅修正指向被移动文件的链接，保留其正文、标签、链接文字和代码示例。

## 安装包与边界

`npm run package` 生成本地测试包，ZIP 只含 `flomo-safe-sync/main.js`、`flomo-safe-sync/manifest.json`、`flomo-safe-sync/styles.css`；不含 `data.json`、账号信息、测试库和开发测试代码。
发布目录另提供三个独立运行文件、ZIP 和 `SHA256SUMS.txt`，可用于后续 BRAT 预发布。

本轮未操作用户真实笔记库，未验证 Windows 或真实账号全量同步，未上传 GitHub。已经删除的笔记不能通过移动重建，仍需使用“检查缺失文件”恢复；多份同编号笔记、无法确认归属的附件、无效 YAML 会保留原文件并报告原因。目录整理不修复已经损坏的同步受管区标记。
