## 实际 Obsidian 验证

运行环境：macOS，Obsidian 1.13.7，Node.js 22.23.2。使用隔离 profile 和测试 Vault；未导入真实笔记或账号。

界面检查结果：

- 五个水平设置标签页正确显示，窄窗口标签栏可横向滚动。
- 1280 像素视口中“启动时同步”的说明和开关位于同一行，实测设置行高度 42 像素。
- 文件名的六个分段时间变量可插入、保存、重载并实时预览；时间变量参考默认展开。
- 范围标签按 `aria-level` 1、2、3 展示三层结构；三个已选标签自动生成三个只需选择目录的映射行。
- YAML 右侧显示整篇笔记，包含两个插件受管区，并单独标出标签合并区和用户可编辑区。
- 标签更新例外显示为两个有缩进引导线的层级分支。
- 浅色、深色和 560 像素窄视口渲染通过；窄视口设置区宽和内容滚动宽均为 345 像素，无页面横向溢出。
- 禁用再启用产品插件后，已保存的文件名和 YAML 草稿继续存在。

实际文件流程继续通过更新、归档、重载恢复和 Obsidian 本地回收站。新增图床流程使用产品同步引擎和真实 Vault API：创建本地图片嵌入，模拟图床插件写回远程链接并删除本地源图，再同步同一 Flomo 图片。结果保留图床链接、本地源图仍不存在、附件错误数为 0。

截图和机器结果位于隔离测试目录的 `evidence-v031`；测试入口在执行前校验固定测试 Vault，不包含在安装包中。

## 包与边界

`npm run package` 会清空旧产物目录，生成只含 `main.js`、`manifest.json`、`styles.css` 的安装 ZIP，并额外生成 BRAT 发布目录和对应 SHA256 清单。发布目录缺少任何独立运行文件或出现额外文件时，打包检查会失败。

- 未登录真实 Flomo 账号或验证实时 API 兼容性。
- 图床替换识别限定在插件正文受管区，并要求当前图片数量及顺序可与已记录的 Flomo 图片可靠对应；无法确认时不猜测。
- 修改图片目录不迁移历史附件，删除和归档仍保留附件。
- 尚未在最低声明版本 Obsidian 1.2.3 上实测。
