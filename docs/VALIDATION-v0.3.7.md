# Flomo Safe Sync v0.3.7 验证记录

验证日期：2026-09-07

## 自动化检查

`npm run check` 通过：

- TypeScript 类型检查和生产构建。
- 同步核心测试。
- 受管区安全测试：38 个拒写场景、13 个兼容场景。
- 插件安全流程：18 项。
- v0.3.x 流程：69 项。

新增覆盖：

- 本地文件缺失与普通冲突分别统计；无远端变化、冻结标签下仍提示缺失。
- 同编号笔记失去 YAML 注释标记后，恢复预览和执行均阻止重复创建，保留原文件和记录。
- 无效 YAML、重复 `flomo_slug` 字段、带引号的字段名不会隐藏已有身份。
- 恢复预览完成后重新出现的同编号文件阻止导入。
- 虚构批量场景：180 条 memo 中 50 条范围外、130 条旧路径缺失，其中 2 条已在别处存在；仅 128 条能导入，后续同步不再重复创建它们。

## 恢复组件界面

将实际 `settings-tab.ts` 的恢复组件与 `styles.css` 挂载到独立浏览器测试页，使用虚构 memo 和 Obsidian Setting 适配层；未连接真实账号。

实际点击验证通过：

- “全选可导入”勾选 128 项；“取消全选”将选择归零并禁用执行。
- 执行回调只收到 128 个可导入编号，2 个已有身份未进入请求。
- 需检查分组展开后显示已有路径和阻止原因，没有导入复选框。
- 明暗主题可读，560px 窄窗口无水平溢出；执行按钮在滚动列表上方。

这是恢复组件验证，不代表本轮重新完成了整个 Obsidian 应用的端到端验收。原生 Obsidian `processFrontMatter` 的身份保护用例已补入测试入口，本轮未执行该原生入口。

## 真实环境边界

本轮通过真实账号进行完整远端快照的只读读取，核对了当前范围和本地同步记录；模板渲染校验通过。没有将真实账号内容纳入测试夹具、源码或发行包。

未执行真实 Vault 的重新导入、路径关联、保护标记修补、归档或删除。真实笔记恢复仍待使用者更新后勾选执行；已有同编号但路径或标记异常的笔记仍需单独处理。

## 安装包与公开下载

安装 ZIP 只包含 `flomo-safe-sync/main.js`、`flomo-safe-sync/manifest.json`、`flomo-safe-sync/styles.css`，不含 `data.json`。

Release 提供独立运行文件、安装包、源码包、验证报告和 `SHA256SUMS.txt`。构建、包内容、CRC 与公开下载摘要在发布流程中逐项核对；摘要以 Release 的 `SHA256SUMS.txt` 为准。
