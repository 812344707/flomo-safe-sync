# Flomo Safe Sync

Flomo → Obsidian 桌面同步插件。当前版本 **0.3.10**，基于
[Watermelon4000/flomo-obsidian-sync](https://github.com/Watermelon4000/flomo-obsidian-sync)。

插件只维护明确标记的正文、Flomo 属性及标签的 Flomo 部分，保留手工补充。

## v0.3.10 更新

- 修改默认保存目录、标签目录或图片目录后，自动迁移范围内的已有笔记和已记录的附件，并更新链接。
- 目录输入完成后按 Enter 或离开输入框才保存；输入过程中不移动文件。

## 连接与同步

在“连接与同步”中登录 Flomo。顶部显示连接状态、上次同步时间及立即同步按钮。
启动同步可单独开关；同步间隔为 0 时关闭定时同步。读取标签不会导入笔记。

接口使用 Flomo 网页端内部 API。令牌保存在当前 Vault 的插件数据中；当前真实账号
兼容情况需要单独验证。开发与验收结果见 [验证报告](docs/VALIDATION-v0.3.10.md)。

## 保存位置和文件名

所有目录为 Vault 内相对路径，例如 `00-Flomo收件箱`。输入框可搜索已有目录，
也可以填写待创建的新目录；绝对路径和 `..` 等路径不接受。

默认文件名：

```text
{{yyyy-MM-dd}}_{{HH-mm-ss}}_{{title:20}}_{{slug:8}}
```

新安装使用上述推荐格式。升级前已经保存的默认模板会继续原样生效，设置页会显示
“采用推荐默认格式”按钮；只有主动采用并保存后才会改变后续新导入笔记的文件名。

自定义模式支持自由组合下列变量、文字与分隔符：

| 变量 | 含义 | 示例 |
| --- | --- | --- |
| `{{yyyy-MM-dd}}` | 推荐日期格式 | `2026-09-01` |
| `{{yyyy-MM-dd_HH-mm-ss}}` | 推荐日期时间格式 | `2026-09-01_08-09-10` |
| `{{yyyyMMdd-HHmmss}}` | 推荐紧凑日期时间格式 | `20260901-080910` |
| `{{title}}` / `{{title:20}}` | 正文首行／最多 20 字 | `第一条写作想法` |
| `{{slug}}` / `{{slug:8}}` | 完整编号／编号前 8 位 | `abcdef12` |
| `{{first_tag}}` | 第一个标签 | `写作`；无标签时为 `untagged` |

`title` 和 `slug` 的截取长度可以编辑。日期格式采用 Unicode 风格字段的文件名安全子集：
`yyyy/yy` 年、`MM/M` 月、`dd/d` 日、`HH/H` 24 小时、`mm/m` 分、`ss/s` 秒，可用
`-`、`_`、`.` 或空格分隔。大小写有区别：`MM` 是月份，`mm` 是分钟。请使用小写
`yyyy` 表示年份、小写 `dd` 表示日期；大写 `YYYY`、`DD` 在通用日期规范中有不同含义。

以下旧变量继续兼容，旧模板无需修改：`{{date}}`、`{{time}}`、`{{year}}`、
`{{month}}`、`{{day}}`、`{{hour}}`、`{{minute}}`、`{{second}}` 和
`{{YYYY-MM-DD-HHmmss}}`。设置页把它们单列为“兼容旧格式”，并提供
[Unicode 日期字段规范](https://unicode.org/reports/tr35/tr35-dates.html#Date_Field_Symbol_Table)
与插件变量参考链接。

文件名及笔记模板使用编辑草稿：点击保存后生效，切换标签页保留草稿，重新加载插件后
恢复已保存配置。切换到默认模式不会覆盖已保存的自定义模板。

修改文件名或笔记模板只影响新导入笔记。修改保存目录或目录映射会自动移动已有文件，
同时保持现有文件名。目标同名时追加短编号及必要的序号，不覆盖原文件。

## 同步范围与目录映射

| 模式 | 行为 |
| --- | --- |
| 包括 | 命中任意所选标签才同步；空选择不导入 |
| 排除 | 命中任意所选标签则跳过；空选择同步全部，包括无标签 memo |

标签按完整名称匹配，`医学` 不自动匹配 `医学/论文`。支持搜索、多选和手动输入；带 `/`
的标签按树形层级列表缩进显示。选择父级时，当前列表中的全部子孙标签会同时被明确选中；
取消父级时同步取消其子孙标签；部分子级被选中时父级显示半选。父子标签在同步判断中
仍分别按完整名称精确匹配。
范围之外的已有文件原地保留；重新进入范围后，按更新方式补同步。

同步范围和目录映射位于同一棵标签树中。左侧勾选包括或排除状态，右侧为当前同步范围内
的标签设置专属 Vault 文件夹；清空目录即改用“默认保存目录”。子级默认折叠，搜索时
自动显示匹配标签及完整上级路径。目录映射示例：

```text
写作 → 20-写作素材
医学/论文 → 30-医学研究
```

范围内的 memo 多条命中时采用第一条已设置映射，只保存一份；未命中目录映射时保存到
页面中明确设置的默认位置。目录映射不会扩大同步范围。

### 图片与附件

开启本地化后，图片及附件保存到 `<图片保存目录>/<memo编号>/`。新下载的文件使用
源链接摘要及文件名命名，避免正文顺序变化导致不同图片共用文件名。

修改图片保存目录会移动已有 memo 已记录的本地图片和附件，并修正笔记内链接及同步记录。
默认目录下的图片目录会随默认目录调整，独立指定的图片目录保持独立。仅移动有归属依据的
附件，不搬走整个文件夹；未记录的个人文件留在原处。正文之外的附件会补充链接，正文已引用的图片不会重复添加。
如果其他 Obsidian 插件把受管正文里的本地图片链接替换为图床地址，本插件会在下一次
正文更新时识别该替换，并记录“Flomo 原地址 → 图床地址”。之后继续使用图床地址，不再
重新下载该图片。图床插件应先成功写回远程链接，再按其自身规则删除本地文件。
下载失败或关闭本地化时保留远端链接。删除和归档规则均不清理附件。

## 完整笔记模板

“笔记模板”编辑区直接显示首次导入使用的完整 Markdown 源码。用户可以修改受管区之外的
YAML 字段、标题、固定文字和正文结构，并实时查看首次导入结果。模板可使用与文件名相同
的日期及内容变量。

属性受管区、正文受管区及其安全标记完整显示。受管字段和标记不能删除或改写；
`{{flomo_tags}}` 必须在 YAML 中保留一个，`{{flomo_content}}` 必须在正文受管区内保留一个。
这些约束用于确认笔记身份并安全更新。用户 YAML 不接受重复字段、`tags` 或以 `flomo_`
开头的字段。

模板只用于之后首次导入的新笔记，不批量改写历史笔记。v0.3.1 保存的 YAML 字段模板在
升级时自动放入完整模板的用户 YAML 区，迁移可重复执行。

## 更新与安全

### 已有笔记的更新方式

| 方式 | 普通更新范围 |
| --- | --- |
| 正文与属性（默认） | 正文受管区、Flomo 属性及标签合并 |
| 仅正文 | 正文受管区，YAML 保持不变 |
| 仅属性 | Flomo 属性及标签合并，正文保持不变 |
| 仅首次导入 | 已有笔记不更新正文和属性 |

首次导入均生成完整笔记。正文与属性分别记录应用版本，切换方式后可以补上此前跳过
的更新。删除和恢复状态由独立规则处理，不受普通更新方式限制。

保存目录改变后，会自动移动范围内的已有笔记；“同步范围 → 按当前目录整理”也可整理之前已经设错目录的文件。
迁移在本地执行，无需登录或下载，保留笔记编号、现有文件名、手写正文和属性，只修正受影响的文件链接。
文件与附件的移动意图在操作前保存；操作中断后重载插件可继续，错误原因显示在“连接与同步”。
归档、回收站和范围外记录不参与本次目录整理。如果已删除同步生成的 Markdown 文件，可在“更新与安全 → 本地缺失笔记”
检查并勾选重新导入，可用“全选可导入”选择这批笔记。插件会按当前目录设置创建新文件；普通同步只报告缺失，不会自行重建。

如果 Vault 其他位置已有同编号笔记，该项列入“需检查”并禁止重新导入。目录整理可以在旧路径缺失且仅有一份编号明确的文件时找回实际路径并移动原文件。
即使 YAML 注释保护标记被属性编辑器或其他插件移除，编号唯一、YAML 可解析的文件仍可迁移。
编号重复、YAML 损坏或多份身份冲突时暂停该项；普通同步的正文和属性写入仍要求完整受管区，目录整理不会修补这些标记。

“标签更新例外”使用层级缩进展示，保留原版的首次导入后冻结／完全跳过。例外只在同步范围内生效，
命中任意例外标签即采用例外规则；移除例外标签后按更新方式恢复同步。

### 远端删除

| 动作 | 本地处理 |
| --- | --- |
| 保持原样 | 笔记不变，仅记录远端状态 |
| 标记已删除（默认） | 保留文件，写入 `flomo_status: deleted` |
| 移入归档目录 | 标记后移动，保留原相对路径；冲突时追加短编号 |
| 列出后手动移入回收站 | 同步只生成列表；用户勾选后再次核对远端快照并执行 |

回收站列表显示名称、路径和检测时间。实际调用 Obsidian 的本地 `.trash`，保留手工
正文和附件；定时同步不会自行执行待处理回收站操作。

Flomo 恢复 memo 后，归档笔记移回原路径，原位置被占用时报告冲突；回收站笔记须先
手动从 `.trash` 恢复原文件，再同步。切换删除规则不会撤销已完成的归档或回收站操作。
归档及恢复使用 Obsidian 的文件管理接口，并遵循 Obsidian 更新链接的设置。
目录整理使用 `Vault.rename` 和 `Vault.process`，自动修正已有笔记中指向被移动文件的链接，
避免弹出更新链接询问窗口；不会改变 Obsidian 的全局链接偏好。链接文字、手写段落和代码示例保留。

### 受管区保护

正文与元数据受管区使用下列保留标记：

```text
# flomo-sync:frontmatter:start
# flomo-sync:frontmatter:end
<!-- flomo-sync:content:start -->
<!-- flomo-sync:content:end -->
```

每个标记必须唯一、独占一行、顺序正确；元数据标记位于顶部 YAML 内，正文标记位于
YAML 之后。`flomo_slug` 必须唯一、位于受管元数据内并与待处理 memo 一致。
冲突时保留原文件，不推进相应更新版本。不要在受管笔记中复制完整标记作示例。

`tags` 合并保留手工标签；旧 `flomo_tags` 在属性更新时迁移。普通改写使用 Obsidian
的原子读取修改接口；移动与回收站操作记录逐文件意图和结果，支持失败后的重试。

删除判定基于过滤之前的全量响应。响应缺失、无效数据、重复记录、重复游标、网络失败
或超出分页上限均中止整轮写入；有效空数组仍表示空快照。结构校验无法证明上游服务
没有返回结构正确但内容错误的列表。

## 安装与升级

```bash
npm ci --ignore-scripts --no-audit --no-fund
npm run check
npm run package
```

将 `dist/flomo-safe-sync-0.3.2.zip` 解压后的 `flomo-safe-sync` 目录放入：

```text
<Vault>/.obsidian/plugins/flomo-safe-sync/
├── main.js
├── manifest.json
└── styles.css
```

升级时替换这三个文件，保留原有 `data.json`，再重新加载插件。
旧配置自动迁移为包括模式，标签来自原目录映射；自定义模板、图片目录、标签例外与
同步记录保留。默认更新方式为正文与属性，默认删除动作为标记。迁移可重复执行。

升级兼容原则：已经保存的设置是唯一数据来源。新版只为缺失的新字段补默认值；只有
旧版数据结构确实需要转换时才在内存副本上迁移，不会用新版默认值覆盖已有选择。
安装包始终只含上述三个运行文件，不含 `data.json`。每次发布必须通过“当前设置原样
加载”“`false`、`0`、空列表不被默认值替换”和“安装包不含设置文件”的回归检查。

插件仅支持桌面版，最低声明版本保持 Obsidian 1.2.3；本轮实机验证版本为 1.13.7。

## 开发验证

`npm run check` 包含类型检查、基础功能、受管区安全、旧插件流程、新版同步流程和生产构建。
自动化逻辑测试使用虚构响应和内存文件，实际 Obsidian 检查使用独立测试库。
复现步骤、截图和验证边界见 [验证报告](docs/VALIDATION-v0.3.2.md)。
